problem-solving toolkit.

Core idea: Before writing custom infrastructure, ask whether the Java language, standard library or JVM already provides the capability.

01

Object & Type Design

Model business concepts and control how those concepts can change.

Classes

Scattered data and behavior are hard to reason about.
Java capability
Classes combine state and behavior around a meaningful concept.
Pattern
Encapsulation · Object Modeling
class Order {
  private final List items;

  Money total() {
    return items.stream()
      .map(Item::price)
      .reduce(Money.ZERO, Money::add);
  }
}
Better product
Business rules stay close to the domain object and are easier to evolve.

Interfaces

Concrete dependencies make change and testing expensive.
Java capability
Define a contract without prescribing the implementation.
interface PaymentGateway {
  PaymentResult pay(Payment payment);
}

class CheckoutService {
  private final PaymentGateway gateway;
  CheckoutService(PaymentGateway gateway) {
    this.gateway = gateway;
  }
}
Pattern
Programming to an interface · Dependency Inversion
Better product
Payment providers, test doubles or infrastructure can change independently.

Encapsulation

Any caller can put an object into an invalid state.
Java capability
Private state plus controlled operations protect invariants.
class Order {
  private OrderStatus status;

  void markPaid() {
    if (status != OrderStatus.CREATED)
      throw new IllegalStateException();
    status = OrderStatus.PAID;
  }
}
Pattern
Information Hiding

Polymorphism

Growing if/else or switch logic becomes fragile.
Java capability
Different implementations can satisfy the same contract.
interface PaymentMethod {
  PaymentResult pay(Money amount);
}

class CardPayment implements PaymentMethod { ... }
class UpiPayment implements PaymentMethod { ... }
Pattern
Strategy · Polymorphism

Records

Data-only types require repetitive boilerplate.
Java capability
Compact syntax for data-centric, shallowly immutable value carriers.
record CreateOrderCommand(
  Long customerId,
  List<Long> productIds
) {}
Useful for
DTOs, commands, responses, configuration/value objects.

Enums

Strings and numbers create invalid states and typos.
enum OrderStatus {
  CREATED, PAID, CANCELLED
}
Pattern
Strongly Typed Closed Set
Benefit
Compiler-assisted domain state instead of magic strings.

Sealed Types

You need polymorphism but want a controlled set of valid alternatives.
sealed interface PaymentResult
  permits Success, Failed, Pending {}

record Success(...) implements PaymentResult {}
record Failed(...) implements PaymentResult {}
Pattern
Controlled Polymorphism · State Modeling
02

Data & Transformation

Store, access, transform and aggregate data with type-safe standard abstractions.

Collections

Every application needs groups of data with different access patterns.
List<Order> orders;
Set<String> uniqueIds;
Map<Long, Customer> customers;
Queue<Job> pendingJobs;
Pattern
Choose the data structure by access/use pattern
Rule
List = sequence · Set = uniqueness · Map = key/value · Queue = processing order.

Generics

Casting and weak typing push errors to runtime.
interface Repository<T, ID> {
  T findById(ID id);
}

Repository<Order, Long> orders;
Pattern
Compile-time Type Safety · Reusable Abstraction

Optional

Missing values represented by null cause accidental failures.
Optional<Customer> findCustomer(Long id);

return repository.findById(id)
    .map(Customer::name)
    .orElse("Guest");
Pattern
Explicit Absence
Boundary
Best for expressing optional return values; not a universal replacement for null everywhere.

Lambda

Small pieces of behavior require verbose code.
orders.sort(
  (a, b) -> a.total().compareTo(b.total())
);
Pattern
Behavior as a Value

Streams

Loops mix filtering, transformation and aggregation with mutable control flow.
var paidTotals = orders.stream()
  .filter(Order::isPaid)
  .map(Order::total)
  .toList();
Pattern
Pipeline · Declarative Transformation
Benefit
Business data flows become easier to read and modify.

Collectors

Transformed data still needs grouping, counting and aggregation.
var byCustomer = orders.stream()
  .collect(groupingBy(Order::customerId));
Pattern
Aggregation · Grouping
03

Failure & Resource Management

Make failure explicit and make resource lifecycle safe.

Exceptions

Operations fail and callers need a structured failure path.
try {
  payment.charge();
} catch (PaymentException e) {
  recoverOrReport(e);
}
Pattern
Failure Propagation · Exception Boundary

Custom Exceptions

Generic exceptions hide business meaning.
throw new InsufficientBalanceException();
Pattern
Domain-Specific Failure

try-with-resources

Files, streams and connections must be closed even when work fails.
try (var reader =
     Files.newBufferedReader(path)) {
  return reader.readLine();
}
Pattern
Deterministic Cleanup

AutoCloseable

Custom resources also need a standard lifecycle contract.
class Connection implements AutoCloseable {
  public void close() { /* cleanup */ }
}
Pattern
Resource Lifecycle Contract

Everyday Application APIs

Use standard abstractions for text, time, files and data movement instead of reinventing them.

String

Applications constantly manipulate text.
var normalized =
    email.trim().toLowerCase();
Key idea
Immutable text with standard search, comparison, replacement and formatting operations.

Regex

Simple string operations are insufficient for pattern-based validation or extraction.
Pattern.compile(
  "[A-Z]{2}-\\d{6}"
);
Pattern
Pattern Matching

java.time

Dates, durations and time zones are easy to model incorrectly.
var expiry = Instant.now()
    .plus(Duration.ofHours(24));
Pattern
Explicit Time Modeling

Files / Path

File handling becomes verbose and platform-dependent.
Path path = Path.of("orders.json");

if (Files.exists(path)) {
  var json = Files.readString(path);
}
Pattern
Filesystem Abstraction

I/O

Data must move safely between the application and external resources.
Input
  ↓
Reader / Stream
  ↓
Application
  ↓
Writer / Stream
  ↓
Output
Pattern
Stream-Based Data Flow

Concurrency

Execute independent work efficiently while controlling shared state.

Threads

Multiple independent execution paths are sometimes required.
Thread.ofPlatform()
  .start(() -> processJob());
Pattern
Concurrent Execution
Boundary
Prefer higher-level task abstractions when possible.

Executors

Creating and managing threads manually doesn't scale well.
ExecutorService pool =
    Executors.newFixedThreadPool(8);

pool.submit(() -> process(job));
Pattern
Task-Based Concurrency

CompletableFuture

Independent I/O work should not require blocking each step.
getCustomer()
  .thenCompose(this::getOrders)
  .thenApply(this::buildSummary);
Pattern
Async Composition · Pipeline

Concurrent Collections

Multiple threads need safe access to shared collections.
var cache = new ConcurrentHashMap<Long, Customer>();

cache.computeIfAbsent(id, this::load);
Pattern
Thread-Safe Shared Data

Atomics

Small shared state updates need atomic operations.
var requests = new AtomicLong();

requests.incrementAndGet();
Pattern
Lock-Free Atomic State

Synchronization

Concurrent access to mutable state can create race conditions.
synchronized void updateState() {
  // protected critical section
}
Pattern
Mutual Exclusion · Coordination
Design rule
Reduce shared mutable state before reaching for locks.

System Integration

Communicate with other systems using standard Java networking and security primitives.

HTTP Client

Applications need HTTP communication without hand-built protocol plumbing.
var request = HttpRequest.newBuilder(uri)
    .GET()
    .build();

var response =
    client.send(request,
      HttpResponse.BodyHandlers.ofString());
Pattern
Standard HTTP Client Abstraction

URI

Raw string concatenation makes resource addresses fragile.
URI uri = URI.create(
  "https://api.example.com/orders/42"
);
Pattern
Structured Resource Addressing

Networking

Specialized applications may need lower-level network communication.
ServerSocket server =
    new ServerSocket(8080);
Pattern
Socket / Channel Communication
Boundary
For normal REST business services, prefer higher-level HTTP APIs/frameworks.

Security APIs

Applications need cryptographic primitives and secure protocols.
MessageDigest digest =
    MessageDigest.getInstance("SHA-256");

byte[] result =
    digest.digest(data);
Pattern
Standard Security Primitive
Rule
Use established cryptographic libraries and protocols; never invent cryptography.

Java 17 & Java 21

These LTS releases materially improve how modern Java applications model data, state and concurrency.

JAVA 17 · LTS

More expressive domain modeling

  • Sealed classes/interfaces — explicitly control inheritance and model finite domain alternatives.
  • Records — concise immutable data carriers, excellent for DTOs, commands and value objects.
  • Pattern matching for instanceof — reduce casting boilerplate and make type checks clearer.
  • Text blocks — make multi-line JSON, SQL and templates much easier to read.
  • Switch expressions — make branching expression-oriented and safer.
  • Helpful NullPointerExceptions — better diagnosis when null-related failures occur.
Java 17 is a strong baseline for modern enterprise Java because it combines LTS stability with significantly cleaner language constructs.
JAVA 21 · LTS

Modern concurrency + cleaner control flow

  • Virtual threads — make high-concurrency, I/O-heavy applications much easier to scale using a thread-per-task programming model.
  • Record patterns — deconstruct records naturally during pattern matching.
  • Pattern matching for switch — express type/state branching more directly.
  • Sequenced collections — common operations for collections with a defined encounter sequence.
  • String templates were previewed in Java 21, not a permanent Java 21 feature; treat preview features separately from the stable baseline.
Java 21 is especially important for server-side development because virtual threads can simplify scalable blocking-I/O concurrency.
Practical upgrade lens: Java 17 improves modeling and readability; Java 21 adds a major step in concurrency ergonomics. For a new enterprise application, think in terms of the LTS baseline, runtime compatibility, framework support and operational constraints—not just language features.
